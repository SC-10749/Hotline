# 规格 S-015：CI 校验修复（技能流历史契约 · agent 事件 · 注册取消挂死 · mvnw 可执行位）

> 状态：已实现
> 日期：2026-11-24
> 影响范围：`skill-center/test_agent_tools.py`、`python_backend/infrastructure/service_registry.py`、`java_backend/mvnw`（文件权限位）、`docs/spec/modules/execution.md`

## 1. 背景与目标

CI 工作流在 `SC-10749/Hotline` 上三红二绿（前端构建绿）：

- **Python 校验红**：`skill-center/test_agent_tools.py` 6 项失败（1 错 5 败）。根因不是执行逻辑错，而是测试契约落后于已上线的两条行为：① SSE `agent` 事件（前端据此切助手形态）自「需求分析bot」起每轮必发，测试的事件序列断言没跟上；② 技能流会读会话历史，但**只**用于取需求正文（需求助手产出的那轮回答），历史本身不进模型提示词。测试里把 `storage.session_messages` 设成抛异常，等于禁止读历史，直接把技能流打成失败路径。
- **Java 校验红**：`java_backend/mvnw` 在 Git 里是 `100644`，Linux 上 `./java_backend/mvnw` 没有可执行位，作业 5 秒即以 Permission denied 失败。代码与测试本身没问题（本地 `mvn verify` 76 项全过）。
- **修掉上面两条之后才会暴露的雷**：CI 的 Python 是 3.11，而 `NacosRegistry._maintain` 用 `asyncio.wait_for` 包住发布调用。Python 3.11 的 `wait_for` 在外层任务被取消时会把取消替换成内部异常（3.12 起改用 `asyncio.timeout` 才修掉），于是取消信号被吃掉，`_maintain` 的 `while True` 继续循环，`stop()` 里 `await self.task` 永远等不到 → 单测进程挂死。本机 3.13 不复现，所以一直没被发现；CI 一旦越过前面的失败步骤就会在这里挂到作业超时。

目标：让 CI 三个作业在 Ubuntu 上可复现地通过，并把上述行为写成明确的契约（代码 + 测试 + 文档），避免再次漂移。

- 不改 `agent` 事件、SSE 事件顺序、前端模式切换逻辑。
- 不动 Java 业务代码、依赖版本与打包配置。
- 不改 Nacos 注册协议与元数据语义（apiVersion、draining、就绪状态同步）。

## 4. 接口契约

无新增或变更的接口与字段。既有 SSE 事件契约在此确认：

- `agent`：每轮事件流的第一条事件，`content` 是本轮实际助手类型（`chat` / `skills` / `deep` / `file` / `ppt`）。前端 `frontend/src/modules/chat/useChat.js` 按此切模式条与底部输入区形态。

## 5. 行为约定

- **技能流的历史口径**：技能流会读会话记录，但只取最近一次带「需求条目」标记的回答（`_requirement_brief`），作为交接内容注入系统提示；其余会话历史**不得**进入模型提示词，模型每轮只看到当前问题（`test_current_question_only_on_each_request`）。
- **测试口径**：`skill-center/test_agent_tools.py` 用「历史哨兵文本不出现在模型请求里」表达「技能流不把历史喂给模型」，不再用「不得调用 `session_messages`」表达——后者与需求正文交接互斥。
- **事件序列口径**：技能流事件序列以 `agent` 开头：`agent → thinking → context_snapshot → text → recommend → complete`（工具调用轮再插入 `tool_start` / `tool_end`）。
- **注册循环的取消语义**：`NacosRegistry.stop()` 取消 `_maintain` 任务后必须能等到它结束。发布调用用 `asyncio.timeout`（3.11+）而不是 `asyncio.wait_for`，保证外部取消原样传播为 `CancelledError`；否则 3.11 上取消会被换成内部异常，注册循环不退出、停止流程挂死。
- **构建脚本口径**：CI 以 `./java_backend/mvnw` 调用 Maven 包装器，仓库内该文件必须以可执行位提交（`100755`）。

## 8. 已知限制与后续

- `skill-center/test_skill_disclosure.py` 在 Windows 本机仍失败：换行符（CRLF vs LF）、创建符号链接需管理员权限、无 `os.mkfifo`、SQLite 文件被占用无法删除。CI 跑 Ubuntu，这些用例在 Ubuntu 上会真正执行路径校验分支（符号链接越界、非普通文件拒绝），相关拒绝逻辑见 `python_backend/modules/skills/registry.py:_local_text`。
- 技能流在「上下文服务关闭 + 存储为真实 `Storage`」时会退回 `session_messages` 读全量历史取需求正文；生产默认开启上下文服务（`HOTLINE_CONTEXT_ENABLED` 默认 true），走 `context_messages`。
- `NacosRegistry.stop()` 里注销与关闭客户端仍用 `asyncio.wait_for`：这两次调用自身有 5 秒超时，不会无限等待；若调用方取消 `stop()`，3.11 上取消会被换成内部异常并被 `except Exception` 吞掉，行为退化为「继续走完关闭流程」，不影响挂死风险，改成 `asyncio.timeout` 只是收敛、不在本��范围。
- `docs/spec/index.md` 中 S-007 编号重复由并发提交引入，不在本次范围内，另行顺延。
