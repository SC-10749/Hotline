# 规格 S-013：工具治理与产物归属修复

> 状态：已实现
> 日期：2026-11-23
> 影响范围：execution 工具治理、MCP 路由、产物存储与下载路由、retention 清理、Harness 前端请求头

## 1. 背景与目标

三条链路存在真实缺口：

1. **MCP 调用绕过治理**：`POST /harness/mcp/servers/{tool_id}/tools/{tool_name}/call` 直接调用远端工具，不经过 `prepare_tool_call`，运行级白名单与人工审批都不生效。同时审批策略有两套口径——登记接口只接受 `risk-based` / `always`，而 `enforce_approval` 只认 `always` / `required`，结果 `risk-based` 的高风险工具**从不触发审批**。
2. **产物归属靠自报**：校验完全依赖客户端自报的归属请求头；记录 owner 为空时对所有人放行；前端把归属请求头名写死为 `X-Harness-Owner`，Harness 设置里改 `artifactOwnerHeader` 后前后端不一致。
3. **审批清理提前一天**：保留期用字符串比较时间戳——审批表 `created_at` 是 SQLite `CURRENT_TIMESTAMP`（空格分隔），截止时间是 ISO `T`/`Z`，空格字符小于 `T`，于是**同一天已裁决的审批会被提前整整一天清掉**，审计链出现缺口。

目标：审批策略只有一个判定口径；MCP 调用必须过审批；产物归属默认拒绝而不是默认放行；保留期按真实时间判断。

## 2. 非目标

- 不引入用户账号体系（项目仍是共享密钥 + 本地操作者模型）。
- 不做审批批量预授权、不做策略表达式。
- 不改 Agent 工具调用链路的既有行为，只统一判定口径。
- 不做审计链签名与防篡改。

## 3. 数据模型变更

无表结构变更。MCP 审批复用 `harness_approval`：`run_id` 与 `tool` 都记 `mcp:<tool_id>:<tool_name>`，便于按工具查最近一次批准。

## 4. 接口契约

### 4.1 审批策略判定（唯一口径）

`python_backend/modules/execution/tools.py:approval_required(record) -> bool`：

| 登记策略 | 风险 | 是否需要审批 |
| --- | --- | --- |
| `always` | 任意 | 是 |
| `risk-based` / `required` | `high` | 是 |
| `risk-based` / `required` | 其它 | 否 |
| 缺失或未知 | 任意 | 否 |

`enforce_approval` 与 MCP 路由共用这一个函数。

### 4.2 MCP 工具调用

`POST /harness/mcp/servers/{tool_id}/tools/{tool_name}/call`

- 登记的 MCP 服务器工具需要审批时：
  - 治理库里存在该标识**已批准且未过期**的记录 → 放行执行；
  - 否则创建审批请求（`status=pending`）并返回 **409**，detail 为「该 MCP 工具需要人工审批（请求编号 approval-xxx），批准后重试」。
- 不需要审批时行为与现状一致。

### 4.3 产物归属

- `ArtifactStore.register` 的 `owner` 变为必填且非空：空归属登记直接 `ValueError`「产物登记必须带归属身份」。
- `GET /harness/artifacts/{id}/download` 与 `/preview`：
  - 记录 owner 为空 → 403「产物未登记归属，无法访问」；
  - 请求头缺失 → 403「缺少归属身份请求头 <name>」；
  - 不匹配 → 403「产物归属身份不匹配」；
  - 归属请求头名取 Harness 设置 `artifactOwnerHeader`，同时兼容默认名 `X-Harness-Owner`。
- 前端：归属请求头名跟随 Harness 设置，不再写死。

### 4.4 审批保留期

`purge_approvals` 用 `datetime(created_at) < datetime(?)` 比较，两种时间戳格式都按真实时间判断。

## 5. 行为约定

- 审批策略判定只有一份实现；登记接口的 `approval_policy` 取值不变（`risk-based` / `always`），两者现在都能真正触发审批。
- MCP 审批是「先拒绝、批准后重试」，不是调用中阻塞等待；审批记录出现在 Harness「待审批」列表，批准后原样重试即可通过；记录过期（`expires_at` 到期）后需要重新审批。
- 归属校验默认拒绝：没有归属就没有下载权。
- 保留期仍只按 `created_at` 判定，只修比较方式。

## 6. 验收标准

- [ ] 登记 `risk-based` + 高风险的 MCP 服务器，调用其工具返回 409 并产生一条待审批记录；批准后重试可执行。
- [ ] `always` 策略的工具同样需要审批；`risk-based` + 低风险不拦。
- [ ] owner 为空的产物记录下载返回 403；owner 不匹配返回 403；匹配返回 200。
- [ ] 无 owner 的登记被拒绝。
- [ ] 同一天内裁决的审批不会被保留期清理提前删掉；超过保留期的仍会删。
- [ ] 前端归属请求头名跟随 Harness 设置。

## 8. 已知限制与后续

- 归属仍是「使用者自报」，没有身份体系；本次只把默认行为从放行改成拒绝。
- MCP 审批不阻塞等待调用方，需要人工批准后重试。
- 历史产物（owner 为空）下载会被拒绝，需要重新登记或人工补归属。
