# 规格 S-007：角色机器人与二次元头像

> 状态：已实现
> 日期：2026-11-23
> 影响范围：`python_backend/seed_bots.py`、`frontend/src/App.vue`、`frontend/src/style.css`、`frontend/src/assets/bot-*-avatar.jpg`、`data/harness-bots.db`

## 1. 背景与目标

机器人页原本只有「需求分析助手」一个机器人，形象与提示词都是单点的。实际使用里需要一组可切换的专业角色（产品、前端、后端、AI、运维、测试），让同一个入口按角色分工干活，同时在界面上能一眼分辨当前启用的是谁。

目标：
- 在现有机器人机制（`BotStore` + 人设注入）上增加 6 个角色机器人，不改接口、不改表结构。
- 每个角色配一张二次元头像，并在机器人页把头像贴进界面（列表小头像 + 详情大头像 + 角色角标贴图）。
- 角色提示词保持短句、结论先行、可执行。

## 2. 非目标

- 不改 `harness_bot` 表结构、不加字段、不加新的机器人路由。
- 不给角色机器人登记 `harness_tool`（只有需求分析助手保留 agent 工具入口）。
- 不做「多机器人同时开启」——全局仍然同一时间只留一个开启。
- 不改聊天页助手头像、不做头像上传。

## 3. 数据模型变更

无。仍用 `harness_bot`（`bot_id/name/instruction/skills/enabled`）与 `harness_bot_session`。

## 4. 接口契约

无新增路由。既有 `GET/POST /harness/bots`、`GET/PUT/DELETE /harness/bots/{bot_id}` 字段不变，角色机器人与需求分析助手走同一份契约。

前端约定：`frontend/src/App.vue` 的 `BOT_META` 按**机器人名称**映射 `{ avatar, icon, accent }`：
- `avatar`：`frontend/src/assets/bot-*-avatar.jpg`（1:1，1024×1024）。全组统一画风：**柔和唯美的日系水彩二次元插画**——水彩晕染与纸张质感、细淡勾线、通透皮肤、含水光大眼、粉蓝淡紫渐变背景配透明蝴蝶与漂浮光斑、圆形构图四周留白；以一张参考图作为 `reference_images` 逐个出图，保证 7 个角色画风一致
- `icon`：Lucide 图标组件，作为头像右下角贴图角标
- `accent`：主题色，写进 CSS 变量 `--bot-accent`，供描边与角标使用

## 5. 行为约定

- 角色机器人由 `python -m python_backend.seed_bots` 幂等播种：按名称 upsert，**已有机器人保留用户设置的开启状态**，不覆盖用户在界面上的开关。
- 新建角色机器人一律 `enabled=False`；需求分析助手仍是默认开启项。
- 技能绑定按名称解析成技能编号：产品经理绑 `requirement-analysis`，测试工程师绑 `hotline-tdd`，其余不绑技能。
- 头像与角标都靠名称匹配：机器人被改名后头像失效（回退到 Lucide 机器人图标），这是既有行为，不额外维护编号映射。

- [x] 机器人页列表显示小头像，详情显示大头像 + 右下角角色角标贴图；无头像的机器人仍显示 Lucide 机器人图标。
- [x] `npm --prefix frontend run build` 通过。

## 8. 已知限制与后续

- 头像按名称匹配，改名即失效；要长期稳定需在 `harness_bot` 加头像字段（本次未做）。
- 7 张头像单张 300–390KB，合计约 2.4MB，未做压缩；后续要瘦身可统一降到 512px 或转 WebP。
- 角色机器人不带技能时只能靠角色指令与工具清单工作，没有各自的技能包。
