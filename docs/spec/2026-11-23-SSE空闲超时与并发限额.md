# 规格 S-009：SSE 空闲超时与共享并发限额

> 状态：草案
> 日期：2026-11-23
> 影响范围：`python_backend/api/routers/execution.py`、`python_backend/config.py`、`python_backend/fastapi_app.py`、`.env.example`、`README.md`

## 1. 背景与目标

SSE 长连接有两个已知缺口（README 已列在待建设项里）：

1. **没有空闲超时**。`event_stream` 只要运行状态还是 `running` 就无限循环，每 15 秒发一个 `: keep-alive`。一条卡住的运行会永久占住一条连接和一个执行线程。
2. **没有共享并发限额**。同时打开多少条流完全不受限，恶意或误用的客户端可以一次性开满，把 Worker 与线程池耗尽。

本规格补上这两道保护。

## 2. 非目标

- **不实现 SSE 空闲重连**：前端已有 `last-event-id` 断点续传，流结束后由前端决定是否重连。
- **不做每用户配额**：本项目是单用户部署，只做全局共享上限。
- **不改事件格式**：`idle_timeout` 是新增的事件类型，其余事件不变。

## 4. 接口契约

### 4.1 新增配置

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `HOTLINE_SSE_LIMIT` | `0` | 同时打开的 SSE 流上限；0 表示不限制 |
| `HOTLINE_SSE_IDLE_TIMEOUT` | `0` | 空闲超时秒数；0 表示不启用 |

### 4.2 行为约定

**空闲超时**：以「最后一次有内容的事件」为准，不把 `: keep-alive` 心跳算作活动。

超过 `HOTLINE_SSE_IDLE_TIMEOUT` 秒没有任何内容事件时，流主动结束：

- envelope 模式（`/execution/runs/{run_id}/stream`）：发 `event: idle_timeout`，`data` 为 `{"runId": "..."}`。
- 非 envelope 模式（`/agent/*/stream`）：发 `data: [IDLE_TIMEOUT]`。

运行本身**不因此被取消**：Worker 继续跑，前端可以用 `last-event-id` 恢复。

**并发限额**：新建流时检查当前打开的流数量，达到上限则返回 **503**，响应 detail 为 `同时打开的流超过上限 N`。名额在流结束（含异常中断）时释放。

## 5. 验收标准

1. `HOTLINE_SSE_LIMIT=0` 与 `HOTLINE_SSE_IDLE_TIMEOUT=0` 时行为与改动前完全一致。
2. 限额生效时，第 N+1 条流返回 503；前面任一条流结束后可以再次新建。
3. 空闲超时以内容事件为准，keep-alive 心跳不延长空闲计时。
4. 单测覆盖：限额未达上限时不拒绝、超限拒绝、释放后可重用、0 表示不限制、空闲超时的取值规范化。

## 7. 已知限制

- 限额是进程内的，多 Worker 部署时每个进程各自计数，不是全局总数。
- 空闲超时不区分「运行还在跑但很慢」和「运行卡住」，两者都会被断流，靠断点续传恢复。
