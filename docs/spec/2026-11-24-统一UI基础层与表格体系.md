# 规格 S-019：统一 UI 基础层与表格体系

> 状态：已实现
> 日期：2026-11-24
> 影响范围：frontend/src/ui/（新增）、frontend/src/main.js、frontend/src/style.css、frontend/src/harness.css、frontend/src/App.vue、frontend/src/modules/{automation,skills,bots,documents,chat,profile,evaluation,harness}/**、DESIGN.md、docs/spec/modules/harness-console.md

## 1. 背景与目标

用户反馈「有些页面的样式和组件 UI 太丑」，要求统一管理项目 UI 与样式。本轮用 UI skill（Anthropic `frontend-design` + Vercel `web-design-guidelines`）做一次全站体检并落地统一体系。

体检（本地 dev 5180 + Java 8080 + Python 8888，真实数据）确认的问题：

1. **顶层独立页双标题**。`App.vue` 里 `page-sidebar-header h2` 与主区 `standalone-header h1` 都写页面名，一屏出现两次同名大标题：插件页「插件/插件」、机器人页「机器人/机器人」、文档库页「文档库/文档库」、导出页「历史聊天/导出历史聊天」、自动化页「自动化/安排任务」。
2. **主操作按钮重复**。自动化页「新建任务」出现 3 次（侧栏 + 内容区工具条 + 空态 CTA），插件页「上传技能包」与文档库页「上传文档」各 2 次（侧栏 + 工具条）。
3. **七套互不相同的表格实现**，列宽、表头、hover、斑马纹各写一套：
   - `resource-table` / `resource-table-head` / `resource-row`（Harness 目录与治理页）
   - `dataset-table` / `dataset-head` / `dataset-row`（测评集）
   - `release-table` / `release-table-head` / `release-row`（发布治理）
   - `machine-table` / `machine-header` / `machine-row`（运行总览）
   - `benchmark-table`（真 `<table>`，测评基准）
   - `eval-matrix-table` / `eval-trace-table`（真 `<table>`，Agent 测评）
   - `plugin-row` / `plugin-list`（插件、定时任务列表）
4. **状态标记三种形态**：`dataset-state`（圆点）、`plugin-state`（胶囊）、`health-mini`（裸圆点），同一「在线/启用」语义外观不统一。
5. **空态各自实现**：`page-empty-state`（大图标 + h2）、`release-empty`、`bot-overview-empty`、`bot-nav-empty`，标题层级与留白不一致。

本轮目标：建立**一处** UI 基础层（`frontend/src/ui/`），把表格、列表、空态、状态标记、面板标题、按钮位收敛到同一套类；所有页面不再各自实现表格与空态。

## 2. 非目标

- 不改视觉世界：沿用 `static/console/tokens.css` 的色板与 `DESIGN.md` 的密度、圆角、字号。
- 不引入组件库、不加依赖、不做暗色主题重做。
- 不改任何后端接口、字段与业务逻辑。
- 不重写聊天页的对话流与消息排版（那是另一套信息密度，需单独评估）。

## 5. 行为约定

### 5.1 一屏一个页面标题

独立页的页面名只由主区 `standalone-header h1` 承载。侧栏标题改成不重复页面名的分组名；侧栏本身没有分组结构时（自动化、插件、文档库、导出）直接不渲染侧栏标题，只留主操作入口。侧栏自带分组标题的页面（机器人、个人中心）不再叠加外层标题。

### 5.2 主操作按钮只出现一次

每个独立页的主操作（新建任务、上传技能包、上传文档、导出聊天）只保留一处：侧栏或内容区工具条二选一。空态里的 CTA 保留（空态是首次引导，与工具条按钮不同时可见），但按钮文案与位置按统一规范。

### 5.3 统一表格体系

新增 `.ui-table` 体系，取代上述七套实现：

- 结构：容器 `.ui-table`（横向滚动）→ 表头 `.ui-table-head` → 行 `.ui-row`；行内主次信息用 `<strong>` / `<small>` 表达，不另起标签。
- 列宽由语义列类决定（`.ui-cols-machine`、`.ui-cols-approval`、`.ui-cols-trace`、`.ui-cols-trend`、`.ui-cols-mcp`、`.ui-cols-workspace`、`.ui-cols-dataset`、`.ui-cols-release`、`.ui-cols-generic`），每类的列数必须等于表头单元格数。
- 行 hover 有反馈，表头固定底色与最小高度，长标识与时间列给足最小宽度，状态与操作列固定宽度靠右。
- 语义化的真 `<table>`（`benchmark-table`、`eval-matrix-table`、`eval-trace-table`）统一加 `.ui-table-real` 基类（`<table>` 语义 + 同一套表头/行样式与 hover）。

### 5.4 统一状态标记

新增 `.ui-status`（圆点 + 文字，胶囊底色）与四档语义：`ok`（成功）/ `warn`（等待）/ `err`（失败）/ `idle`（未记录、停用）。原 `dataset-state`、`plugin-state`、裸圆点状态统一到这一套，保留旧类名作为兼容别名。

### 5.5 统一空态

新增 `.ui-empty`：图标（可选，36px）+ 一句结论 + 一句说明 + 可选 CTA。空态标题用 `h3`（页面已有 `h1`，空态不再使用 `h2`），删除重复的主操作按钮。

### 5.6 统一面板与按钮位

- `.ui-panel` / `.ui-panel-head` / `.ui-panel-actions`：面板标题与操作区的统一写法（标题 `h3` + 一行辅助说明 + 右侧操作区）。
- 主操作按钮只用 `primary-button`（黑底）/ `secondary-button`（描边）/ `text-action`（行内文字操作）/ `text-action danger`（破坏性）四种，不新增第五种。

## 6. 验收标准

改造过程中发现并修掉的真实缺陷：

1. 列类原先挂在表头与行上，两处要各写一遍且容易漏写。改为列类只挂 `.ui-table` 容器，用 CSS 变量 `--ui-cols` / `--ui-cols-min` 向下继承给表头与行，表头与行不可能再错位。
2. `AgentEvalPanel.vue` 的 scoped 规则仍指向已删除的 `.resource-table-head` / `.resource-row`，10 列结果明细表实际无列宽定义。改用 `.ui-cols-eval-results`。
3. `evaluation-report-row` 与测评集行存在多余的第 7 个子元素（`ArrowRight`），与 3 列 / 6 列栅格不符。测评集行去掉箭头（整行可点），历史报告行改用 4 列 `.ui-cols-report`。
4. 概览页机器表 6 列、发布记录 9 列、灰度推进 6 列此前都没有列类定义。补 `.ui-cols-machine-summary`、`.ui-cols-release-record`、`.ui-cols-rollout`。
5. `App.vue` 去掉四个顶层页的侧栏后，`.standalone-page` 仍固定 `248px + 1fr` 两列。补 `:not(:has(> .page-sidebar))` 单列规则。
6. 自动化页与插件页的工具条主操作在空态时与空态 CTA 重复出现。工具条按钮改为仅在有数据时显示。

## 8. 已知限制与后续

- 聊天页（消息流、输入区）沿用现有实现，未纳入本轮统一；其密度与工作台页面不同，另立规格评估。
- 无表头的记录行（灰度观察记录、质量门禁记录、版本快照等）没有表头行，仍靠 `.ui-cols-history` 保证行子元素数与列宽一致；后续若要加表头，直接补一行 `.ui-table-head`。
- 代码地图页（CodeMapPage）自成一体的可视化布局，本轮未纳入统一层，也未改动。
- `static/console/console.css`（静态技能控制台）不在 Vue 应用内，本轮不合并样式，仅保证令牌一致。
- 暗色主题沿用 `tokens.css` 的 `--h-*` 映射，新增基础层只用共享令牌，不写死颜色。
