# 规格 S-018：Harness 菜单页信息层级与状态标注修正

> 状态：已实现
> 日期：2026-11-24
> 影响范围：frontend/src/HarnessApp.vue、frontend/src/harness.css、frontend/src/modules/harness/{useResources.js,panels/*Panel.vue}、frontend/src/style.css、DESIGN.md、docs/spec/modules/harness-console.md

## 1. 背景与目标

Harness 控制台侧栏有 14 个菜单项（3 组）。本轮用 UI skill 的 Operate 模式审一遍这些页面，目的是把「操作型界面」该有的可扫读性和状态真实性补齐。

浏览器实测（本地 dev 5180 + Java 网关 8080 + Python 8888，真实数据）确认了以下缺陷：

1. **状态标注失真**。机器与运行时、追踪与日志两页顶部显示「未接入运行 API」和黄色横幅「尚未接入运行控制 API / 当前展示规划范围和待接入状态」，但同页下方就列着 68 个真实 Worker 节点和 100 条真实 Trace。根因有两处：
   - `HarnessApp.vue` 的 `sectionMode`/`sourceLabel` 用一长串三元只覆盖了部分 section，`machines`/`approvals`/`observability`/`artifacts` 全部落进兜底分支 `'planned'`。
   - `useResources.js` 里 `resourceConnected` 是 `computed`，却在 `refreshResourceData` 中被 `resourceConnected.value = true/false` 赋值。computed 只读，赋值无效且在 Vue 里会告警，导致 `resourceConnected` 永远为 `false`，页面底部恒显「未连接治理 API」。

2. **表格列数与表头不匹配**。`workspace-cols` 定义 5 列，但机器表实际 7 列（Worker/进程/最近心跳/当前运行/容量/状态/错误）、审批表 6 列、Trace 事件表 7 列（事件/类型/级别/工具/时间）。多余列被挤到第二行，渲染成「Worker 一行、状态 另起一行」的错位。Trace 运行表的 run_id 与时间戳列过窄，长 ID 和 ISO 时间戳折行。

3. **页面标题重复**。壳层 `page-heading-row` 已输出当前菜单名（如「机器与运行时」），各 Panel 内又各写一遍同名 `release-toolbar h2`。同一屏出现两次同样的大标题。

4. **概览页文案与事实矛盾**。运行总览正文写「下列汇总指标与节点表为演示数据，实际运行请进入执行任务」，而同页数据其实来自真实运行记录；页脚又写「总览指标来自今日真实运行记录」。概览页还把 68 个节点全部铺开，其中 67 个是几天前的离线节点，淹没了唯一在线节点的信号。

5. **死控件**。壳层顶栏的「搜索」图标与「快速查找 Ctrl K」按钮都执行 `$refs.searchField?.focus()`，但 `searchField` 这个 ref 定义在 RunsPanel 内部，壳层取不到，点击无反应；Ctrl K 也没有对应快捷键实现。

6. **Panel 之间代码重复**。AgentsPanel 与 WorkspacesPanel 是同一份模板的两个拷贝，各自带 `activeSection === 'agents' ? ... : ...` 分支去渲染对方的内容；实际渲染时只有一个 section 命中，等于两份文件里各有一半是死代码。

## 2. 非目标

- 不改任何后端接口、字段、路由与返回结构。本次只动前端展示层与状态标注。
- 不引入新的菜单项、筛选器、图表库或依赖。
- 不重做视觉世界。沿用现有 `DESIGN.md` 的中性色板、8px 圆角与 13–14px 正文密度，只修层级与标注。
- 不动聊天页、个人中心、机器人页等 Harness 以外的页面。

## 3. 数据模型变更

无。

## 4. 接口契约

无新增或变更的接口。仍使用既有的 `/harness/machines`、`/harness/approvals`、`/harness/observability/*`、`/harness/artifacts` 等路由。

## 5. 行为约定

### 5.1 每个 section 的状态与来源标注一一对应

状态只有两档，取值来自各模块真实的连接标志，不允许用兜底分支猜测：

| 档位 | 含义 | 顶栏呈现 |
| --- | --- | --- |
| `live` | 该 section 的数据来自后端实时接口 | 成功色圆点 + 来源文字 |
| `demo` | 该 section 的接口未接通 | 警示色圆点 + 写明缺哪个 API |

14 个 section 都已接后端数据源，因此不再保留 `planned` 档，也删掉「尚未接入运行控制 API」的黄色横幅：该横幅与同页的真实数据自相矛盾。

对应关系（`HarnessApp.vue` 内以映射表表达，取代现在的三元链）：

- `overview`/`runs` → 执行服务连接状态
- `evaluations` → 测评服务
- `releases` → 发布目录
- `agents`/`workspaces` → 资源目录
- `tools` → 工具目录
- `models` → 模型目录
- `skills` → 按当前页签取 Catalog 或本地安装目录
- `machines`/`approvals` → 治理 API 的节点/审批连接状态
- `observability` → 只读运营 API
- `artifacts` → 产物登记（只读）
- `settings` → 设置 API

任何 section 都不显示「尚未接入」横幅；接口未接通时由顶栏来源标签与页脚连接指示说明。

### 5.2 连接标志是可写状态

`useResources.js` 中 `machinesConnected`/`approvalsConnected`/`traceConnected` 是普通 ref，由对应请求的成功与否决定；`resourceConnected` 保持为只读 computed，作为三者的派生值。任何地方不得给 computed 赋值。

### 5.3 表格列与表头一一对应

每张表的 `grid-template-columns` 列数必须等于表头单元格数。列宽按内容分配：标识与长文本列可折行，状态与操作列固定最小宽度，操作列靠右。

### 5.4 标题层级唯一

一屏只有一个一级标题（壳层的 `page-heading-row h1`）。Panel 内不再重复菜单名；Panel 内标题一律从 `h3` 起，归属其所属的 `h2` 区块。空 Panel 标题行时，区块直接以 `h3` 呈现。

### 5.5 概览页只呈现有效信号

运行总览展示真实指标与节点汇总：节点表按「在线优先、离线折叠」呈现，标出在线/离线数量与进入节点管理的入口。不再宣称数据是演示数据。

### 5.6 壳层顶栏只保留能工作的控件

顶栏的搜索图标与「快速查找 Ctrl K」在当前实现下没有可聚焦目标，直接移除，不用占位符冒充可用。快捷键能力后续若要做，另立规格。
