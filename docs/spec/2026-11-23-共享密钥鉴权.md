# 规格 S-008：共享密钥鉴权

> 状态：已实现
> 日期：2026-11-23
> 影响范围：`java_backend/`（新增 Filter 与配置）、`python_backend/config.py`、`python_backend/fastapi_app.py`（新增中间件）、`frontend/src/api.js`、`frontend/src/App.vue`、`.env.example`、`README.md`

## 1. 背景与目标

当前 Java 入口与 Python 能力 API **都没有任何身份校验**：

- `java_backend` 全库检索不到 `HTTPBearer` / `APIKeyHeader` / `OAuth2` / `Depends(auth)`。
- `python_backend` 同样没有任何鉴权依赖或中间件。
- `python_backend/api/routers/profile.py` 的 `/harness/profile/credentials` 能写入模型 API Key，`/harness/profile/credentials/test` 能用该 Key 真实发请求。

本地默认绑定 `127.0.0.1`，此时裸奔不构成实际风险。但只要出现下面任一情况，整个 Agent 执行面与模型凭据即完全暴露：

- 把 `HOTLINE_JAVA_HOST` / `DODO_HOST` 改成 `0.0.0.0`；
- 走 Nacos 跨主机部署；
- 把 8888 端口暴露到内网。

本规格给这条链路加一道共享密钥校验，让「暴露出去」不等于「任意可调用」。

## 2. 非目标

- **不做多用户账号体系**：不引入用户表、注册登录、密码哈希、角色权限。
- **不做 OAuth / JWT / Session Cookie**：不引入会话中间件或 token 签发服务。
- **不改前端页面结构**：不新增登录页、不做路由守卫。密钥由用户在设置页填一次，存 `localStorage`。
- **不保护静态资源与健康检查**：`/health`、`/health/ready`、静态资源仍可匿名访问，供探针与首屏加载使用。
- **不改既有业务接口的请求体或响应体**：只增加一个可选的请求头校验。

## 3. 数据模型变更

无表结构变更。凭据仍存 `data/harness-credentials.db`，本规格不触碰其存储方式。

## 4. 接口契约

### 4.1 新增请求头

| 头名 | 说明 |
| --- | --- |
| `X-Hotline-Token` | 共享密钥明文值。两端使用同一个环境变量 `HOTLINE_API_TOKEN` |

### 4.2 新增配置

| 变量 | 端 | 默认 | 说明 |
| --- | --- | --- | --- |
| `HOTLINE_API_TOKEN` | Java / Python | 空 | 空表示**不启用**校验（保持现有行为）；非空则启用 |

Java 侧映射为 `hotline.security.token`。

### 4.3 校验规则

两端规则一致：

1. 配置为空 → 放行一切（不启用）。
2. 请求头 `X-Hotline-Token` 与配置值相等 → 放行。
3. 否则 → HTTP 401，响应体 `{"code": "UNAUTHORIZED", "message": "缺少或无效的访问令牌"}`。

**放行的路径**（不校验）：
- Java：`/health/live`、`/health/ready`
- Python：`/health`、`/health/ready`

Java 转发到 Python 时**必须**把 `X-Hotline-Token` 一并带上，否则 Python 侧会拒掉 Java 的转发请求。

### 4.4 前端行为

- 密钥存 `localStorage` 键 `hotline-api-token`。
- `frontend/src/api.js` 里所有 `fetch` 统一带上该头；没有配置时不加（后端也未启用）。
- 设置页提供一个输入框用于填写与清除密钥。
- SSE（`fetch` + `ReadableStream`）同样带头。

## 5. 行为约定

- 校验发生在**最外层**：Java 用 Servlet Filter，Python 用 FastAPI 中间件，因此覆盖所有路由，含后续新增路由。
- 密钥比较使用**恒定时间比较**，避免时序侧信道。
- Java 的 `/health/ready` 会探测 Python 是否就绪；该探测走内部路径，不携带密钥，因此 Python 侧的健康端点必须放行。
- 启用鉴权后，**未携带密钥的浏览器访问会被 401**。这是预期行为，README 需要写明配置方式。

## 6. 验收标准

1. `HOTLINE_API_TOKEN` 未设置时，两端行为与改动前完全一致（现有测试全绿）。
2. `HOTLINE_API_TOKEN=secret` 时：
   - Java：不带头 → 401；带对 → 200；带错 → 401。
   - Python：不带头 → 401；带对 → 200；带错 → 401。
   - 两端的 `/health*` 仍返回 200。
   - Java 带密钥转发后，Python 收到的是同一个 `X-Hotline-Token`。
3. 前端带密钥请求能成功，不带则收到 401 并提示。
4. Java 单测与 Python 单测均覆盖上述行为。

## 8. 已知限制

- 密钥由用户自行分发；前端存在 `localStorage`，同机其他进程可读取。对「同机单用户」够用，不防同机恶意进程。
- 不做按用户隔离；所有持有密钥的人权限相同。
