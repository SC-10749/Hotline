# 规格 S-001：同会话并发子任务

> 状态：**已实现**（2026-11-23，Redis 模式与浏览器端均已实测）
> 日期：2026-11-23
> 影响范围：`python_backend/modules/execution/{store,parallel,tools,engine}.py`、`python_backend/workers/execution_worker.py`、`python_backend/runtime/agent_runtime.py`、`python_backend/api/routers/execution.py`、`python_backend/application/execution_service.py`、`python_backend/modules/workspaces/context.py`、`frontend/src/{api.js,HarnessApp.vue,modules/execution/ParallelPanel.vue}`、`java_backend/.../PythonProcessLauncher.java`、`java_backend/.../PythonLaunchProperties.java`、`java_backend/src/main/resources/application.yml`

## 1. 背景与目标

同一会话内需要一次派发多个子任务并行执行（例如一次拆解出 8 个调研或实现子任务）。改造前 `execution_run` 的活跃唯一索引是 `(conversation_id)`，同一会话只允许一个活跃运行，子任务会互相阻塞；执行层也缺少「子任务之间彼此隔离、且不污染父会话」的机制。

目标：一次请求派发 N 个子任务，各占一个 slot 并行执行；子任务之间上下文、记忆、任务锁、产物目录互相隔离；前端用一条流式连接同时看到所有子任务的输出。

## 2. 非目标

- 不做父 run 的 LLM 自动汇总（自动分解与汇总成本不可控，先手动派发）。
- 不做子任务之间的共享上下文或共享记忆。
- 不引入线程池或新的并发框架：并发靠多进程 Worker 实现。

## 3. 数据模型变更

| 对象 | 变更 |
| --- | --- |
| `execution_run` | 新增列 `parent_run_id`、`slot`、`workspace_root`（`slot` 空串表示普通对话） |
| 活跃唯一索引 | 由 `uq_execution_active_conversation(conversation_id)` 改为 `uq_execution_active_slot(conversation_id, slot)` |

迁移顺序必须先 `_ensure_columns` 再建索引，否则旧库建索引会报 `no such column: slot`。

## 4. 接口契约

**`POST /execution/runs/parallel`**

- 请求：`{ "conversationId": str, "parentRunId": str?, "tasks": [{ "agent": str, "query": str, "agentId": str?, "workspaceId": str? }] }`
- 限制：单次最多 16 个任务；`query` 为空、`conversationId` 为空直接 400；任一任务非法则整批不创建（单事务批量入队）。
- 响应：`{ "runs": [{ "run_id", "slot", "status", ... }] }`，slot 形如 `sub-0`、`sub-1`（不能用冒号，会拼进目录名）。

**`GET /execution/parallel/stream?runIds=<id1>,<id2>`**

- 服务端 fan-in 合并多路事件，每条事件载荷带 `runId` 与 `eventId`，SSE id 头为 `runId:eventId`。
- 前端只用一条 EventSource，避开浏览器同源 HTTP/1.1 仅 6 条连接的上限。

## 5. 行为约定

子任务与父会话在执行层解耦，以下三处必须使用同一个键，缺一处就会出问题：

| 用途 | 载体 | 说明 |
| --- | --- | --- |
| 任务锁 | `task_key = {conversation_id}#{slot}` | `TaskManager` 按会话独占；注册与释放必须用同一个 task_key，否则 Redis 锁残留到 TTL 过期，同 slot 无法再次派发 |
| 上下文与记忆作用域 | `scope_key = task_key` | `context.begin/prepare/complete` 必须同键；共用父会话作用域会撞记忆乐观锁报 `MemoryConflict`，只改一半报「会话范围不存在」 |
| 历史写入 | `persist_history=False` | 子任务只产出事件与记忆，不写父会话 `ai_session` 历史 |

- 运行态（run_id、工具白名单）由模块全局改为线程隔离，避免并发执行时审批与工具权限串号。
- 重试运行必须继承 `slot`、`parent_run_id`、`workspace_root`，否则重试会退化成普通运行并撞活跃唯一索引。
- 取消按会话停掉全部活跃运行。

## 6. 隔离与工作目录

- 目录：`data/parallel/<父运行或会话>/<slot>/`，写入运行的 `workspace_root`。
- 分配策略三级降级：git 工作区用 `git worktree add --detach`；普通目录 copytree；都失败时只保留独立产物目录。降级不失败子任务。
- 工作区规则（AGENTS.md）从隔离副本加载（`load_workspace_rules(store, workspace_id, root='')` 支持指定根）。

## 7. 前端交互

- `frontend/src/api.js`：`createParallelRuns`、`parallelStreamUrl`。
- `frontend/src/modules/execution/ParallelPanel.vue`：一条 EventSource，按 runId 路由到卡片，展示 slot、状态、流式文本、隔离目录。
- `frontend/src/HarnessApp.vue`：「执行任务」区新增「并行派发」按钮并挂载面板。

## 8. 验收标准

- [x] 同一会话一次派发 8 个子任务，8 个 slot 互不阻塞。
- [x] 普通对话（slot 空串）仍只允许一个活跃运行，既有语义不变。
- [x] 并发执行时 run_id 与工具白名单不串号。
- [x] 多 Worker 并发领取同一批任务不重复领取。
- [x] 所有子任务共用一条 SSE，前端逐条看到各子任务输出。
- [x] 每个子任务拿到独立工作目录，互不覆盖。
- [x] 执行完成后 Redis 无残留锁，父会话历史不被子任务写入。

## 10. 已知限制与后续

- 并发度取决于 Worker 进程数（`HOTLINE_PYTHON_WORKER_INSTANCES`，默认 2）；要 8 路真并发需起 8 个 Worker。
- 执行链路目前没有写文件或脚本类工具，隔离目录暂时只作用于规则与产物根；接入这类工具时应把 `workspace_root` 作为其工作目录。
- MCP 走 stdio 且 cwd 继承 Worker，并发调用时仍共用同一 Worker 的工作目录。
- 工作区文件召回仍走共享索引，只有规则与产物目录做了隔离。
- 真 Redis 未覆盖（本机无 Redis 服务，用 fakeredis 模拟），持久化与集群语义待验证。
