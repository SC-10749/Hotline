# S-011 代码质量收敛与并发改造（存储基类 · 并发改造 · 异常语义）

- 状态：已实现
- 日期：2026-11-23
- 影响范围：`python_backend/infrastructure/`、`python_backend/modules/execution/`、`python_backend/modules/intent/`、`python_backend/modules/documents/`、`python_backend/modules/retrieval/`、`frontend/src/modules/`

## 背景与目标

本仓库的 Python 后端在多轮迭代后积累了三类可收敛的重复与隐患：

1. **SQLite 样板重复**：12 处 `_db()` 上下文管理器、7 处 `_connect()`、21 处 `BEGIN IMMEDIATE` 事务块、8 处 `PRAGMA table_info` + `ALTER TABLE` 补列循环。这些是同一套模式的复制粘贴，改一处漏三处。
2. **并发缺失**：模型调用与嵌入调用大量串行。`PgVectorStore.add_chunks` / `index_document` 逐块调嵌入接口（一次 HTTP 一块），`ExampleVectorStore.warmup` 逐条调嵌入，`DocumentService` 逐张图调视觉模型、逐块抽关系，均可并行。
3. **异常语义模糊**：`ModelClient.chat` 把任何失败都吞成空字符串，与「上游真的返回空」不可区分；`except (ValueError, Exception)` 是冗余写法。

目标：把重复收敛到一处、把可并行 IO 并行化、把「失败」与「空结果」在语义上分开。

## 非目标

- 不改任何 HTTP 接口的字段、路径、状态码。
- 不改 SQLite 表结构与列定义（只改「怎么建表、怎么补列」的代码位置）。
- 不改前端页面结构与交互。
- 不做「为了用设计模式而用」：只有同一段逻辑出现 3 次以上、且形状稳定时才抽。

## 数据模型变更

无。表结构、列定义、索引全部保持不变。

## 接口契约

无对外接口变更。

新增内部模块：

| 模块 | 职责 |
| --- | --- |
| `python_backend/infrastructure/sqlite_base.py` | `SqliteStore` 基类：`_connect` / `_db` / `_transaction` / `ensure_columns` |

## 行为约定

### 1. SqliteStore 基类

- `_connect()` 默认 `timeout=30, isolation_level=None`，`PRAGMA busy_timeout = 30000`。
- 需要 `timeout=10` 的 store（bot / credential / profile / scheduled）用类属性覆盖，**不得**强行统一成 30。
- `_transaction()` 上下文管理器：`BEGIN IMMEDIATE` → 正常结束 `commit()`，异常 `rollback()` 后**重新抛出**。
  - 事务块的语义必须与原实现一致：原代码里 `commit()` 后 `return` 的位置保持不变。
- `ensure_columns(db, table, columns)`：等价于 `python_backend/modules/execution/store.py` 中已有的 `_ensure_columns`，参数顺序一致。
  - 该函数**不是**静态方法，挂在基类上，调用点写法为 `self.ensure_columns(db, table, {...})`。

### 2. 批量与并发嵌入

- `PgVectorStore.add_chunks` / `index_document`：改用 `embed_batch` 一次请求算一批（批大小 16），批与批之间串行——数据库写入是单连接，串行写入更安全。
- 批嵌入失败时**回退到逐条嵌入**（`_embed`），保证行为与改造前一致（原来就是逐条）。
- `ExampleVectorStore.warmup`：示例句互不依赖，用 `ThreadPoolExecutor`（8 并发）并行取回，顺序与原列表一致。实测预热从 42 秒降到 2 秒。
- `DocumentService.caption_images`：每张图的描述是独立模型调用，用 `ThreadPoolExecutor`（4 并发）并行；单张失败只记一条告警，不影响其它图片。
- `DocumentService._extract_relations_batch`：关系抽取按块并行（4 并发），失败的那块不影响其它块。

### 3. 异常语义

- `ModelClient.chat` 失败时**不再静默返回空字符串**：记录一条 `logger.warning`，并仍返回 `""`（调用方的降级逻辑依赖空串，不改返回契约）。
- `except (ValueError, Exception)` 一律简化为 `except Exception`（`Exception` 已覆盖 `ValueError`）。
- SSE 流已开始后发生异常：`AgentEngine._stream_skills` 与 `ModelClient._stream_pieces` 保持现有「不再发帧」的行为，但**不得**吞掉异常本身——异常继续向上抛给调用方，由调用方决定是否补发 error 事件。

## 已知限制

- `SqliteStore` 只统一 SQLite 存储，不覆盖 `PgVectorStore`（PostgreSQL）与 `modules/storage/relational.py`（MySQL/SQLite 双后端）。
- 批嵌入不改变上游限流假设；批大小 16 是保守取值。
- `infrastructure/artifact_store`、`modules/artifacts/store.py`、`modules/memory/store.py`、`modules/skills/catalog.py` 仍保留各自的连接写法：它们的表结构与连接参数差异较大，且不是本次改动引入的重复，强行统一会掩盖真实差异。
- 前端 `HarnessApp.vue` 的 toast 与 `App.vue` 的 toast 未合并：两者是独立应用壳（不同挂载点、不同生命周期），共用一份状态反而会互相干扰。
