# 规格 S-016：机器人页的 CI 工作流开关

> 状态：已实现
> 日期：2026-11-24
> 影响范围：`python_backend/infrastructure/github_workflow.py`（新）、`python_backend/api/routers/ci_workflow.py`（新）、`python_backend/config.py`、`python_backend/fastapi_app.py`、`frontend/src/modules/bots/*`、`docs/spec/modules/harness-console.md`

## 1. 背景与目标

开源仓库的 GitHub Actions CI 每次推送都要跑满三个作业（Python、前端、Java），占公共 runner 时间；而真正的修复动作往往在自己的开发机上完成。需求是：**在项目自���的机器人页里就能开关这个 CI 工作流**，不用每次去 GitHub 网页点。

目标：

- 机器人页有一个「CI 工作流」开关，关掉后推送与 PR 不再触发该工作流；开回来即恢复。
- 开关必须真的作用在 GitHub 上（不是本地假装），状态以 GitHub 返回为准。
- 凭据不进数据库、不进日志、不随请求外传；没配凭据时界面如实说明并置灰，不猜状态。

## 2. 非目标

- 不改 CI 工作流本身的作业内容（Python / 前端 / Java 三段校验保持现状）。
- 不做多仓库、多工作流批量管理；只管一个仓库里的一个工作流。
- 不把开关接进机器人的人设或会话；它是控制台的运维开关，不影响对话。
- 不引入新的 Python 依赖（用 stdlib urllib 调 GitHub API）。

## 3. 数据模型变更

无。不落库：状态以 GitHub 为准，本地不留副本。

## 4. 接口契约

### `GET /harness/ci-workflow`

响应体：

```json
{
  "configured": true,
  "enabled": false,
  "state": "disabled_manually",
  "workflow": "ci.yml",
  "repository": "owner/repo"
}
```

- `configured`：是否配齐了 Token 与仓库地址。未配置时为 `false`，并额外带 `message` 说明原因。
- `enabled`：只有 GitHub 返回 `state=active` 时为 `true`；`disabled_manually` 等其它状态都为 `false`。
- `state`：GitHub 原始状态字符串，原样透传给前端。

### `POST /harness/ci-workflow`

请求体：`{"enabled": true|false}`。响应体同上（执行后重新读一次状态）。

- 未配置凭据：409，`detail` 说明缺什么。
- GitHub 调用失败：502，`detail` 只带状态码或“接口不可用”，不带凭据。

## 5. 行为约定

- 凭据来源：环境变量 `HOTLINE_GITHUB_TOKEN`、`HOTLINE_GITHUB_REPOSITORY`、`HOTLINE_GITHUB_CI_WORKFLOW`（默认 `ci.yml`）。只在本机 `.env` 里配置，不提交仓库、不写日志。
- 关闭语义：调用 GitHub 的 `PUT /repos/{owner}/{repo}/actions/workflows/{workflow}/disable`，工作流整体停用（推送与 PR 都不再触发）；开启用对应的 `enable`。
- 状态真值在 GitHub：前端不缓存判断，每次刷新都重新读后端返回的状态。
- 前端只展示后端给的信息（仓库 + 工作流文件 + 状态），不自己推断仓库名或工作流名。
- 失败不静默：接口报错时前端弹提示说明失败原因，开关保持原状态。

## 6. 验收标准

- [x] 机器人页有「CI 工作流」开关，未配置凭据时置灰并显示原因。
- [x] 关闭调用 GitHub 的 `disable`、开启调用 `enable`，路径含仓库与工作流名。
- [x] 未配置凭据时 `GET` 返回 `configured: false`、`POST` 返回 409。
- [x] GitHub 调用失败返回 502，错误消息里没有 token。
- [x] 后端单测覆盖状态映射、启停路径、未配置与失败分支；前端单测覆盖读写接口与失败提示。

## 8. 已知限制与后续

- 开关依赖 GitHub Token 权限：细粒度令牌需要 “Actions: Read and write”，经典令牌需要 `repo`。没配或权限不足时后端返回 502，界面显示失败原因。
- 只支持一个仓库的一个工作流；多仓库场景需要再扩参数。
- 工作流“停用”与“删掉触发条件”是两件事：这里用的是 GitHub 的 disable，仓库里的 `.github/workflows/ci.yml` 不变，随时可以开回来。
