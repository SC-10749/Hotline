# 规格 S-012：评测可读性

> 状态：已实现
> 日期：2026-11-23
> 影响范围：evaluation 模块、`/evaluation/datasets` 响应、Harness 测评中心（测评总览 / Agent 测评）

## 1. 背景与目标

评测主体（S-002 ~ S-006）已经能跑批、打语义分、做多 run 矩阵，但结果页面上「读不懂」：

- 失败分类几乎全是 `unknown`：`failure_kind_for` 只认 timeout / judge_unavailable / tool_error 与 rubric 显式声明，内容类失败一律归 `unknown`，「失败分类分布」没有信息量。
- 测评集列表的通过率、状态、最近运行是前端写死的假数据（`HarnessApp.vue` 里 `pass: '—'`、`state: '未运行'`）。
- 「历史运行」下拉只显示 `eval-<12hex> · status`，同一个测评集的多次运行分不出来。
- 评测矩阵能并排看判定，但点不开：无法从矩阵跳到某个样本的明细与轨迹。
- 运行出处（模型名、git commit、技能包 sha256、数据集版本）已经落库，页面不展示，复现链路断在最后一步。
- 结果明细只有一句 `detail`，看不到「期望什么」。

目标：一次评测跑完后，人能在 30 秒内读懂结论，并从矩阵定位到具体样本的期望/实际/轨迹。

## 2. 非目标

- 不做置信区间、定期回归任务、基线 diff 快照（沿用 S-006 非目标）。
- 不做样本合成、标注回流、红队（属后续规格）。
- 不引入新依赖，不改表结构，不回写历史结果行。
- 不做评测与可观测 trace 的合并视图（跨模块联表不在本次范围）。

## 3. 数据模型变更

无。`evaluation_*` 表结构不变。失败分类在跑批落库时派生并写入 `evaluation_result.failure_kind`，历史行保留旧值不回填。

## 4. 接口契约

### 4.1 `GET /evaluation/datasets` 响应扩展

每个测评集条目新增 `lastRun` 字段；没有运行过时为 `null`：

```json
{
  "dataset_id": "dataset-1",
  "name": "客服问答",
  "dataset_type": "通用",
  "case_count": 12,
  "lastRun": {
    "runId": "eval-1a2b3c4d5e6f",
    "status": "completed",
    "agent": "chat",
    "epochs": 2,
    "createdAt": "2026-11-23 10:00:00",
    "passRate": 0.3333
  }
}
```

`passRate` 取最近一次运行的 `summary.passRate`；该运行没有摘要时为 `null`。

### 4.2 失败分类取值与判定顺序

`evaluation_result.failure_kind` 新增取值：

| 取值 | 含义 | 证据来源 |
| --- | --- | --- |
| `missing_keyword` | 命中「包含」类规则但输出缺关键词 | rubric.type = contains，或无类型且有期望输出 |
| `output_mismatch` | 输出与期望不一致 | rubric.type = equals |
| `json_mismatch` | JSON 结果不一致 | rubric.type = json_equals |
| `semantic_mismatch` | 模型/语义评分不达标 | rubric.type = model / semantic |
| `trace_assertion_failed` | 轨迹断言不满足 | rubric.type = trace |
| `assertion_failed` | 规则不满足但类型不可再细分 | rubric.type = multi |
| `empty_output` | 助手没有产出任何内容 | 输出为空 |
| `execution_error` | 样本执行抛异常 | 执行异常 |

判定顺序（先命中先返回）：

1. `verdict == passed` → 空串（通过没有失败分类）。
2. `timeout` → `timeout`。
3. `scorer_unavailable` → `judge_unavailable`。
4. rubric 显式 `failureKind` → 用它的值（作者声明优先）。
5. 轨迹里有工具错误 → `tool_error`。
6. 输出为空 → `empty_output`（没产出内容是根因，比「哪条规则没过」更该先说）。
7. rubric 类型可派生 → 上表对应取值。
8. 其余 → `assertion_failed`。

`invalid_rubric` 与 `not_scored` 直接用判定值本身作为分类；被预算跳过的样本仍记 `budget_exhausted`，不参与失败分类派生。

### 4.3 读取侧

`GET /evaluation/runs/{id}` 的 `summary.failureKinds` 结构不变，只是可能包含上表的新取值；前端为新取值补中文标签。

## 5. 行为约定

- 测评集卡片：显示真实通过率与状态；状态取值「运行中 / 已完成 / 需关注 / 未通过 / 未运行」，其中「已完成」且通过率不足 100% 记为「需关注」。
- 运行下拉与矩阵勾选项的标签：`助手 · 测评集名 · 通过率 · 轮数 · 相对时间`；相对时间按浏览器本地时钟算。
- 矩阵单元格可点击：点某个格子切到该运行、该样本的结果明细并打开轨迹。
- 运行出处展示：模型名、git commit（短）、技能包 sha256 列表、测评集版本、重复轮数。
- 期望与实际：选中样本时展示该样本的 rubric 期望与实际输出、评分说明。

## 6. 验收标准

- [ ] rubric 为 `contains` 的失败样本，失败分类是 `missing_keyword`，不再落 `unknown`。
- [ ] `GET /evaluation/datasets` 的每个条目带 `lastRun`，无运行的测评集为 `null`。
- [ ] 测评集列表显示真实通过率与最近运行时间，不再是「— / 未运行」。
- [ ] 运行下拉显示测评集名与通过率，同一测评集的多次运行可区分。
- [ ] 点矩阵格子能定位到该样本的结果与轨迹。
- [ ] 运行详情显示模型、commit、技能摘要、数据集版本。
- [ ] 新增失败分类在页面上有中文标签。

## 8. 已知限制与后续

- `lastRun` 只在最近 200 次运行范围内查找（存储层 `list_runs` 上限），更早运行的测评集不显示最近运行。
- 失败分类只对新跑的批次生效，历史结果行保留旧分类。
- 相对时间按浏览器本地时钟计算，跨时区显示可能与服务器日志不一致。
- 「需关注」只是展示口径（已完成但通过率不足 100%），不参与门禁判定。
