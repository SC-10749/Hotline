# S-007 前端与 AI 引擎分层拆分（DDD 式目录治理）

- 编号：S-007
- 日期：2026-11-23
- 状态：已实现
- 影响范围：`frontend/src/**`、`python_backend/modules/execution/**`、`docs/spec/**`

## 背景与目标

前端主界面 `App.vue`（2251 行）、Harness 控制台 `HarnessApp.vue`（2174 行）与接口层 `frontend/src/api.js`（1009 行）都是单文件巨型文件；后端 `modules/execution/engine.py`（889 行）把任务管理、模型调用、检索编排、门闸全部堆在一个文件里。定位问题、评审改动、并行开发都要在几百上千行里翻。

目标：按能力边界 + 分层（接口层 / 应用层 / 表现层）拆到子文件夹，让每个文件只承担一件事，**行为完全不变**。

## 非目标

- 不改任何 HTTP 接口契约、字段名、事件格式、提示文案。
- 不引入新依赖、不引入状态管理库（Pinia 等）、不做微前端改造。
- 不改后端业务规则；只搬代码与调整可见性。
- 不改前端视觉（`DESIGN.md` 仍是唯一视觉事实源）。

## 目标结构

### 前端 `frontend/src/`

```
src/
  api.js                     # 兼容入口（barrel），保持既有 import 全部可用
  core/
    http.js                  # 基础设施层：unwrap / apiUrl
  modules/
    <capability>/            # 能力边界目录（与后端模块名对应）
      api.js                 # 接口层：这一能力的 HTTP 调用
      use<Feature>.js        # 应用层：composable，状态与用例编排
      <Component>.vue        # 表现层：模板与交互
```

规则：

1. 组件不直接写 `fetch`；一律经由本能力 `api.js`。
2. `api.js` 只做 HTTP 适配，不含业务分支；业务分支留在 composable。
3. composable 以 `use` 开头，返回 `{ state, actions }`：`state` 是 `reactive` 包裹的 `ref/computed` 集合（模板里直接取值即自动解包），`actions` 是用例函数；composable 不直接操作 DOM。
4. 跨能力调用只允许走 `api.js`，不得互相 import 对方的组件内部状态。
5. 组件之间不直接 import，只通过 `props` / `emit` 通信；弹窗、抽屉等交互状态留在父级。
6. 树深、props 会爆炸的场景（嵌套抽屉、面板 tab、能力页面内部）允许用 `provide` / `inject`，注入 key 必须是 `Symbol`，集中放在 `modules/app/keys.js`（主界面）与 `modules/harness/context.js`（控制台）；跨模块调用走 `ctx.hooks` 钩子表，避免模块之间循环依赖。

### 后端 `python_backend/modules/execution/`

```
execution/
  engine.py       # 应用层：AgentEngine 编排（构造、事件工厂、上下文装配、stream 主流程）
  tasks.py        # 基础设施层：TaskManager（任务锁 / Redis 停止广播）
  model_client.py # 基础设施层：ModelClient（模型调用与流式、token 用量）
  grounding.py    # GroundingMixin：检索链路选择、文档/工作区召回、多跳证据扩展
  gates.py        # GateMixin：意图门闸与需求级门闸
  answer_flow.py  # AnswerFlowMixin：通用回答流程（提示组装、上下文装配、降级回答）
  skill_flow.py   # SkillFlowMixin：技能智能体执行流
  constants.py    # 门闸标记、需求交接标记、推荐项文案
```

规则：`AgentEngine` 由四个 mixin 组合而成，公开方法签名与 SSE 事件格式不变；`TaskManager`、`ModelClient` 的公开接口不变，只换文件位置。

## 接口契约

无新增、无删除、无字段变更。`frontend/src/api.js` 的导出名字集合与拆分前一致（barrel 全量再导出；`core/http.js` 只对外暴露 `apiUrl`，`unwrap` 留在模块内部）。

## 行为约定

- SSE 事件类型与顺序不变（`agent` / `thinking` / `step` / `text` / `reference` / `recommend` / `complete` / `clarify` / `usage`）。
- 会话历史、技能面板、文档抽屉、机器人管理、自动化调度的交互与文案不变。
- Harness 控制台各 section 的表格、弹窗与筛选行为不变。
- `python_backend/agents.py` 仍是兼容入口，仍等价于 `modules.execution.engine`。

## 拆分后回归修复（模板绑定丢失导致空白页）

- 现象：Harness 控制台「测评中心」等 8 个页签只剩标题、内容区整块空白；主界面附件上传与通知按钮点击无反应。
- 根因：拆出的面板模板里沿用了壳层的 `activeSection`、`apiBase` 等标识符，但脚本侧没有从注入的上下文解构出来；`v-if="activeSection === 'evaluations'"` 恒为假，组件不渲染任何内容。另有 `harnessApprovalAuditUrl` / `harnessTraceExportUrl` / `skillDirectoryTab` 未绑定，以及机器错误日志区块的 `item` 落在了 `v-for` 作用域之外。
- 修复：8 个面板补 `activeSection`（并修正 `props.apiBase`）、两处下载链接改为从 `modules/governance/api.js` 导入、错误日志区块用 `<template v-for>` 还原成逐条分组；主界面 `ChatView` 改用 `chat.actions.onFilePicked` 与 `pickFile`，`SessionSidebar` 改走 `ctx.hooks.openHome/showNotifications`。
- 防复发：新增 `frontend/src/modules/app/bindings.test.js`，用 `@vue/compiler-sfc` 内联编译全部组件，任何模板标识符没有绑定就判失败。
- 验证：浏览器逐个点击 Harness 14 个页签与主界面 8 个页面，内容区均有内容且无控制台报错；`node --test` 51 项全绿。
